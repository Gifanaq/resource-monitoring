# TPUMON

Сервис проверяет доступность настроенных HTTP-ресурсов и отдаёт их текущие статусы через REST API.

## Требования

Для запуска через Docker нужны Docker Engine с Compose и свободный порт 8000. Для запуска без Docker нужны Python 3.13 и Poetry 2.x.

## Быстрый запуск

Создайте файл настроек:

```sh
cp .env.example .env
```

В `.env` уже заданы `APP_NAME=tpumon`, `APP_ENV=dev` и `API_PORT=8000`. При необходимости измените название приложения и внешний порт. Compose задаёт окружение `prod`, а dev-конфигурация — `dev`. PostgreSQL для запуска не требуется.

Добавьте в `.env` список HTTP-ресурсов для мониторинга. Здесь «сервис» — контролируемый сайт или HTTP-эндпоинт, а не контейнер Docker Compose.

Пример дополнительного содержимого `.env`:

```dotenv
CHECK_INTERVAL_SEC=60
SERVICES='[{"name":"Demo","url":"https://example.org"}]'
```

Замените демонстрационный URL адресом нужного ресурса. `SERVICES` — JSON-массив объектов с полями `name` и `url`. Без этой настройки список пуст и ресурсы не опрашиваются. Интервал между циклами — не меньше 60 секунд; значение 300 задаёт паузу 5 минут. При необходимости укажите `API_PORT`.

```sh
make prod
```

API будет доступен по адресу `http://localhost:8000`, документация OpenAPI — по адресу `http://localhost:8000/docs`, проверка процесса — `http://localhost:8000/health`. Если изменён `API_PORT`, используйте этот порт в адресах.

Для запуска в режиме разработки:

```sh
make dev
```

Для остановки контейнеров:

```sh
make down
```

Для запуска приложения без Docker:

```sh
make install
make run
```

Для проверки HTTP-сервисов без Docker настройте `SERVICES` в `.env`. Переменная `API_PORT` используется только Docker Compose; `make run` запускает API на порту 8000.

Все команды выполняются из корня репозитория.
